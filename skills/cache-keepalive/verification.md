# Verification

## Offline checks

Run the repository's focused check from its root.

```sh
skills/cache-keepalive/scripts/verify.sh
git diff --check
```

Install Claude Code 2.1.289 and TypeScript 5.4 or later for development checks.
`CLAUDE_BIN=/path/to/claude` and `TSC_BIN=/path/to/tsc` select installed executables.
The script creates a temporary home and config directory with an empty
environment. It does not use saved credentials or send a model request.

Native `claude plugin test` stubs settings, time, lifecycle events, and model
responses. A second check loads a temporary copy with `--plugin-dir`, invokes
only `/cache-ping status`, and asserts the CLI reports zero model turns and zero
token usage. That load generates declarations for the installed Claude Code
build. TypeScript checks the copied code and tests against those declarations.
Generated files never enter the repository.

The tests exercise the actual hooks through Claude Code's test runner. A mocked
cache hit proves scheduling and counter behavior. It does not prove that a live
provider retains the main conversation's prefix.

## Opt-in retention experiment

This experiment consumes the account's normal inference allowance or API budget.
Run it only with the user's explicit approval. Keep the same model, effort,
tools, provider, and transcript throughout each observation.

1. Load the Mod with both TTLs explicitly set to `1h` as described in README.md.
2. Complete a normal main turn with enough context to produce cache usage. Record
   the main request time and the cache-read and cache-write counts from Claude
   Code's supported usage diagnostics. Do not copy authentication files.
3. Run `/cache-ping start 2`. Confirm that the first fork runs near 50 minutes
   after the main request. Record its cache-read, cache-write, and output counts.
4. After at least 65 minutes from the original main request, send a normal main
   turn. Record that turn's cache usage separately from the fork's usage.
5. Stop the run. Check that no later timer sends another request.
6. For a comparison, use an equivalent session with keepalive disabled and wait
   past the configured TTL. Cache reuse across sessions can contaminate a
   comparison. Treat the result as inconclusive if isolation is not established.

A useful result includes the Claude Code version, provider, billing mode, both
TTL controls, timestamps, and observed tokens. Redact conversation content.
Partial cache reads, unknown provider policy, or a mismatched prefix do not prove
full retention. Do not claim net savings from a single successful cache hit.

## API evidence

- [Mods API](https://code.claude.com/docs/en/plugins/mods/api) describes forks and native timers.
- [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference) defines lifecycle events and limits.
- [Mod tests](https://code.claude.com/docs/en/plugins/mods/test) run without sign-in or model access.
- [Prompt cache lifetime](https://code.claude.com/docs/en/prompt-caching#cache-lifetime) distinguishes main and non-main TTL controls.
- [Official type declarations](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts) describe fork usage and the last-turn snapshot. Prefer the declarations generated by the installed build when versions disagree.
